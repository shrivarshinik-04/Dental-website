<h2>🔒 Privacy implementation (test environment)</h2>
<p>This copy of the template is a <strong>test environment</strong> for evaluating privacy controls (for example with Zycato by SQ1 Security). The clinic, people and contact details are <strong>fictitious samples</strong> (<code>IS_SAMPLE</code> in <code>src/config/compliance.js</code>), shown with a "Sample details: test environment" badge. Nothing here is a statement that the site complies with any law, and it is not legal advice.</p>
<ul>
  <li><strong>Law in force today:</strong> Information Technology Act 2000, s.43A, and the IT (Reasonable Security Practices and Procedures and Sensitive Personal Data or Information) Rules 2011; CERT-In Directions of 28 April 2022.</li>
  <li><strong>Digital Personal Data Protection Act 2023 and Rules 2025:</strong> only definitions and Board provisions are in force (since 13 Nov 2025). Consent Manager provisions follow about 13 Nov 2026; the main obligations and rights about 13 May 2027 (G.S.R. 843(E); exact day to be confirmed). Features built for those provisions are labelled as such in the UI.</li>
  <li>Code comments cite DPDP sections for features built ahead of commencement; they do not mean those sections already apply.</li>
  <li>Audit, legal matrix, data inventory and plan: <code>docs/audit/</code>. Governing requirements: <code>docs/REQUIREMENTS.md</code>.</li>
</ul>

<h3>Install Node.js (version 20; 18 or newer works)</h3>
<p>The repository pins Node 20 in <code>.nvmrc</code> and requires Node 18+ (<code>engines</code> in <code>package.json</code>). Pick one:</p>
<pre><code># A. nvm (no root needed)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install && nvm use                     # reads .nvmrc

# B. apt on Ubuntu/Debian/WSL (NodeSource)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# C. Behind a corporate proxy (before A/B, and for npm)
export HTTPS_PROXY=http://proxy.example.com:8080 HTTP_PROXY=$HTTPS_PROXY
npm config set proxy "$HTTP_PROXY"
npm config set https-proxy "$HTTPS_PROXY"
export NODE_EXTRA_CA_CERTS=/path/to/corporate-root-ca.pem   # if the proxy inspects TLS
# for apt: echo 'Acquire::https::Proxy "http://proxy.example.com:8080";' | sudo tee /etc/apt/apt.conf.d/95proxy
</code></pre>
<p>Optional: turn off the build tools' anonymous telemetry with <code>NEXT_TELEMETRY_DISABLED=1</code> and <code>CHECKPOINT_DISABLE=1</code>.</p>

<h3>Setup</h3>
<pre><code>npm install
cp .env.example .env            # then fill in the values (see comments in the file)
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"   # ENCRYPTION_KEY
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"      # IP_HASH_SALT, SESSION_SECRET
npm run admin:hash-password -- priya admin 'a-long-password'                  # add the output to ADMIN_USERS
echo 'DEMO_MODE="true"' > .env.development.local   # dev only: show one-time codes on screen
npx prisma migrate dev          # creates prisma/dev.db and seeds the first NoticeVersion
npm run dev                     # http://localhost:3000, admin at /admin
npm run lint                    # ESLint (next/core-web-vitals)
npm run build                   # production build
npx playwright install chromium # once per machine (on Linux also: npx playwright install-deps)
npm test                        # e2e tests: builds into .next-test, uses a synthetic prisma/test.db
</code></pre>
<p><code>.env.development.local</code> is read only by <code>next dev</code>, so production builds never pick up <code>DEMO_MODE</code> by accident.</p>
<ul>
  <li><strong>Existing database:</strong> after pulling new migrations (for example <code>guardian_details</code>, which adds the parent or guardian's mobile and email to bookings), run <code>npx prisma migrate deploy</code>. It applies only the new migrations and keeps existing rows.</li>
  <li><strong>Seed:</strong> <code>npx prisma db seed</code> (re-runnable) stores the notice text for each language as a <code>NoticeVersion</code>. It runs automatically after <code>migrate dev</code>.</li>
  <li><strong>One-time codes:</strong> no SMS or email provider is connected yet, so the Data Rights page and verified grievances need <code>DEMO_MODE=true</code> (see below). Without it the API answers "online verification is not available yet". Codes are never written to logs.</li>
</ul>

<h3>Test-environment flags (<code>.env</code>, see <code>src/lib/env.js</code>)</h3>
<table>
  <thead><tr><th>Variable</th><th>Effect</th></tr></thead>
  <tbody>
    <tr><td><code>DEMO_MODE=true</code></td><td>Shows the one-time code on screen, labelled "Test environment", instead of sending it. <strong>Risk:</strong> anyone who knows a reference ID and the registered phone number or email can open that person's records. Use only with synthetic data in a closed test environment. Refused when <code>NODE_ENV=production</code> (the build and server stop with an error) unless <code>ALLOW_DEMO_IN_PROD=true</code> is also set.</td></tr>
    <tr><td><code>ALLOW_DEMO_IN_PROD=true</code></td><td>Explicit override for a production build used as a test environment. Never set it on a site that real patients use.</td></tr>
    <tr><td><code>FORCE_HTTPS=true</code></td><td>Sends HSTS, <code>upgrade-insecure-requests</code> and COOP, and marks cookies <code>Secure</code>. Only with <code>NODE_ENV=production</code>; set it for <code>next build</code> too, because headers are fixed at build time. Leave it unset to serve a production build over plain HTTP.</td></tr>
    <tr><td><code>TRUST_PROXY=true</code></td><td>Reads the client IP from <code>X-Forwarded-For</code>. Set only behind a reverse proxy that overwrites that header; otherwise clients could spoof it to bypass rate limits.</td></tr>
  </tbody>
</table>
<ul>
  <li><strong>Retention job:</strong> schedule <code>npm run retention</code> daily (cron). Try <code>npm run retention:dry-run</code> first.</li>
  <li><strong>PostgreSQL in production:</strong> set <code>provider = "postgresql"</code> in <code>prisma/schema.prisma</code>, point <code>DATABASE_URL</code> at it, and generate fresh migrations against PostgreSQL. The committed migration is SQLite SQL.</li>
  <li><strong>Changing the notice:</strong> edit <code>src/locales/*.json</code>, bump <code>NOTICE_VERSION</code> in <code>src/config/compliance.js</code>, and add a <code>POLICY_CHANGELOG</code> entry. Visitors are re-prompted. If text changes without a version bump, consent logging refuses to run, so a consent can never point at text the person did not see.</li>
</ul>
